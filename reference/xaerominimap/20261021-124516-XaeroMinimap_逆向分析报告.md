```

  ├─ PushboxHandler   ← 计算模块在屏幕上的合法位置（避开边角、F3、聊天框）
  ├─ HudPresetManager ← 预设动画

             ├─ MinimapProcessor  ← 缩放/形状/FBO 生命周期/洞穴模式开关
             ├─ MinimapWriter     ← 逐帧增量生成贴图数据
             ├─ MinimapWorldManager ← 每个维度/存档的持久化
             ├─ WaypointSession   ← 航点集合
             └─ RadarSession      ← 实体雷达
```

渲染调用链（每帧）：

```
MinimapRenderer.render(session, ctx)
  └─ processor.getRenderer()            // FBO 或安全模式
       └─ renderMinimap(...)
            ├─ renderChunks()           // 抽象方法
            │    └─ MinimapFBORenderer.renderChunksToFBO()   // 两次离屏
            └─ 屏幕层：边框 / 圆形遮罩 / 罗盘 / 玩家箭头 / 越界航点
```

现代版本（26.x）把整个 HUD 画进 GUI 的 **Picture-in-Picture** 渲染状态（`MinimapPipRenderState`），而不是直接往主帧缓冲画——这是为了与 26.x 新的 GUI 渲染管线兼容，对我们无参考价值。

## 核心逻辑

### 1. 数据管线：`MinimapWriter`

**坐标层级**（三层瓦片）：

| 层级 | 尺寸 | 类 | 说明 |
| --- | --- | --- | --- |
| Chunk | 64×64 方块 | `MinimapChunk` | 对应 4×4 个 MC 区块；持有最多 **5 张 64×64 RGBA 纹理** |
| Tile | 16×16 方块 | `MinimapTile` | 对应 1 个 MC 区块；5 个"层"的 RGB |
| 像素 | 1 方块 | — | 一个方块 = 一个像素（zoom=1 时） |

`MinimapTile` 的字段把"省内存"做到了极致：

```java
byte[][][] red   = new byte[5][16][16];   // 5 层 × 256 像素
byte[][][] green = new byte[5][16][16];
byte[][][] blue  = new byte[5][16][16];
short[][]  heights = new short[16][16];   // 表面高度，用于坡度阴影
long[][]   comparisonCodes = new long[16][16];  // 方块状态哈希 → 脏检测
byte[][]   verticalSlopes / diagonalSlopes;     // 与上/左邻居的高度差
```

5 层 = "光照层级"：洞穴模式/亮度叠加下，同一 xz 列在不同埋深看到的方块不同，`level` 越大越亮（`LIGHT_LEVELS = 5`，关闭光照时只算 1 层）。

**增量更新调度**（`onRender()`，每帧调用）：

1. 以玩家所在 chunk 为中心，扫描窗口 `loadingSideInChunks = getLoadSide()`（**9 个 chunk = 576×576 方块**；开启 further zoomout 时 18）；
2. 双缓冲：`loadingBlocks[][]` 写、`loadedBlocks[][]` 读；**一整轮扫完**才在 `updateChunkX/Z` 归零处原子交换，交换时把旧 chunk 的 GL 纹理"过户"给新 chunk（`setGlTexture`），避免重传；
3. 帧预算：
   ```java
   tilesToUpdate = min(elapsed * sizeTiles / fullUpdateTargetTime, 100);
   timeLimit     = min(sinceLastWrite, 50ms) * 86960 ns;   // ≈ 4.3 ms
   ```
   即"按时间配额切块"，最多 100 块/帧，内层按纳秒时间片退出，保证不卡帧；
4. `runNumber % 5 != 0` 时进入 `onlyLoad`：只复用旧 tile（脏区块才重算），**每 5 轮完整重算一次**——用视觉容差换性能；
5. 洞穴层级切换带 `CAVE_MODE_TOGGLE_TIMER` 防抖（`beforeWriting()`），避免地面/洞穴两套数据来回闪。

**表面提取**（`loadBlockColor` / `findBlock`）：

- 从"高度图表面"向下找第一个非空气、非透明、非液体、非树叶、非屏障的方块；
- 透明块（玻璃/水）按 `applyTransparentLayer` 叠在下方颜色之上；
- 坡度阴影：`verticalSlope = clamp(blockY - 上邻居高度, -128, 127)`，`diagonalSlope` 同理取左上邻居——这就是地图上"立体感"的来源；
- 洞穴模式（`getCaving`）：在玩家头顶 3×3（半径由 `AUTO_CAVE_MODE` 决定）检测天光/高度图，若头顶有天花板则返回剖面起始 y；返回 `Integer.MAX_VALUE` 表示"露天，用表面模式"。

### 2. 渲染管线：两次离屏

`MinimapFBORenderer.renderChunksToFBO()` 是整个 mod 画得最快的关键——**两次 512×512 的 FBO 变换**：

```
Pass A  scalingFramebuffer (512×512, RGBA8 + D32)
        正交投影；shaderMatrixStack.translate(256,256,-2000) → scale(zoom)
        对每个可见 chunk 画一个 64×64 的纹理四边形：
            drawX = (chunkX - playerChunkX) * 64 - offsetX
            drawZ = (chunkZ - playerChunkZ) * 64 - offsetZ
        （多纹理批次：按纹理分组提交，一帧几十个 chunk 也只有少量 draw call）
        并在其上画区块网格线（每 chunk 4 条，16 块间距）

Pass B  rotationFramebuffer (512×512)
        identity → translate(halfView, halfView, -2980)
        非北锁时 rotate(-angle)
        translate(-xInsidePixel*zoom, -zInsidePixel*zoom)  // 亚像素补偿，消除移动抖动
        把 Pass A 的纹理整张 512×512 铺上（应用 OPACITY）
        → 在此坐标系里画 element（航点/雷达点/玩家点）

Pass C  屏幕
        取 rotationFramebuffer 的中心子矩形（minimapFrameSize×minimapFrameSize）
        画边框（方形：4 角 + 平铺边条；圆形：按弧长分段的 4 段 ring）
        画玩家箭头（两层阴影 + 主体，随 yaw 旋转，北锁时旋转）
        画罗盘
```

**安全模式兜底**（`MinimapSafeModeRenderer`）：不做离屏，直接逐像素反算世界坐标并采样颜色——

```java
worldX = floor(playerX + ps*offx + pc*offy);
worldZ = floor(playerZ + ps*offy - pc*offx);
```

这条反变换公式是整套坐标系的"标准答案"，移植时直接可用。

### 3. 坐标与投影

- **zoom** 语义：*每方块占几个像素*，取值 `{0.5, 1, 2, 3, 4, 5, 6}`（配置 1..6，开启 further zoomout 后多出 0.5）；
- 可见半径（方块）：
  ```java
  maxVisibleLength = northLocked || circleShape ? viewW : viewW * √2;   // 旋转时对角要够
  radiusBlocks     = maxVisibleLength / 2 / zoom;
  ```
- **北锁角度**：`getRenderAngle(true) = 90°`；否则 `= -90° - cameraYaw`；
- **旋转因子**（两个数覆盖所有投影）：
  ```java
  double angle = toRadians(getRenderAngle(lockedNorth));
  double ps = sin(PI - angle);
  double pc = cos(PI - angle);
  ```
  北锁 ⇒ `angle=90°` ⇒ `ps=1, pc=0` ⇒ 屏幕 x 随世界 x、屏幕 y 随世界 z（北 = −Z 朝上）；
- **元素投影**（`MinimapElementMapRendererHandler`，可直接抄成 Kotlin）：
  ```java
  double dx = (elementX - renderPos.x) * zoom;
  double dz = (elementZ - renderPos.z) * zoom;
  double screenX = ps * dx - pc * dz;
  double screenY = pc * dx + ps * dz;
  boolean outOfBounds = abs(screenX) > halfView || abs(screenY) > halfView;
  ```
  越界标志直接喂给航点渲染器画"贴边箭头"；
- zoom = 0.5 时坐标先做 `x >> 1 << 1` 对齐（避免半像素抖动）；
- 缩放动画：`off *= 0.8^(dt/16.67ms)`（`MultiplyAnimationHelper`，帧率无关的指数逼近）。

### 4. 屏幕层细节

| 参数 | 取值/公式 |
| --- | --- |
| 显示尺寸 | `getMinimapSize() = SIZE配置 × 2`（放大模式固定 500）；绘制时再 /2 |
| 自适应尺寸 | `min(max(55, 2*min(w,h)*130/1080), 250)` |
| 纹理缓冲 | 128 起、2 的幂上取整、上限 512；FBO 固定 512 |
| 圆形遮罩边数 | `max(32, ceil(π*(frameSize+8)/8/4)*4)`（按 8px 弦长近似） |
| 边框图集 | 256×256，四角 16×16（u=192/208/224），边条宽 226 平铺 |
| 未探索区 | 纯黑 + `UNDISCOVERED_OPACITY` |
| 玩家箭头 | 三份叠加：偏移 ±2px 的阴影（alpha²·0.3 / alpha²·0.5）+ 本体 |
| 大尺寸自动北锁 | `mapSize > 180 && 方形` 时强制北锁 |

### 5. 要素（element）系统

```
MinimapElementRenderer<E, Context>   ← 一种要素的渲染器
  ├─ MinimapElementReader<E>         ← 取坐标/是否隐藏
  └─ MinimapElementProvider<E>       ← 迭代数据源
MinimapElementRendererHandler        ← 统一遍历、排序、深度偏移
  ├─ location = IN_MINIMAP   (画在地图坐标系内，随地图旋转)
  └─ location = OVER_MINIMAP (画在屏幕坐标系，不随地图旋转)
```

- 深度：`elementIndex * 0.1`，上限 19490 → 保证航点在雷达之上、雷达在地图之上；
- 航点 `Waypoint`：`(x, y, z, name, initials, color, purpose)`，purpose ∈ {NORMAL, DESTINATION, DEATH, ...}；图标 = 半透明色块 + 首字母（`getInitials()` 取名字前 1~3 字符）；
- 距离过滤 `WAYPOINT_MAX_DISTANCE`、不透明度 `WAYPOINT_OPACITY_ON_MINIMAP`；
- 雷达：实体 → 分类规则树 → 颜色 + 图标，按高度差淡出。

- `MinimapProfiledConfigOptions` 共 **115 个**配置项（SIZE / SHAPE / ZOOM / NORTH_LOCKED / OPACITY / ANTI_ALIASING / SAFE_MODE / CAVE_* / LIGHT_OVERLAY_* / CHUNK_GRID / BLOCK_COLORS / TERRAIN_SLOPES / WAYPOINT_* …）；

## 对 exp8 小地图的移植启示

### 与 Xaero 的关键差异

Xaero 的小地图**永远以玩家为中心**（地图跟着人滚，人钉在正中）；用户对实验八的要求是**以开始建图处为世界原点**，玩家/无人机在其中移动。这对应 Xaero 的 *World Map* 行为，而非 minimap。因此移植时"坐标变换"要反过来：

```
Xaero:  screen = center + (world - player) * zoom * R
我们要:  screen = center + (world - origin) * scale * R     // origin 固定
         playerScreen = center + (player - origin) * scale * R
```

### 建议参数（100 m 级室内/庭院路线）

| 项 | 建议 |
| --- | --- |
| 比例尺 | 默认 `scale = 4 px/m`（小地图直径 200 dp ≈ 50 m 视野），双指缩放 1~16 px/m |
| 瓦片 | 32 m × 32 m / 张（=128 px @4px/m），`Bitmap.Config.RGB_565`（省一半内存） |
| 视口 | 屏幕右下角，直径 `min(screenW, screenH) * 0.28`，外边距 12 dp |
| 形状 | 圆形（`clipPath(Path().apply{ addOval(...) })`），或方形圆角 |
| 朝向 | 默认北锁（无人机场景更稳），可选"机头朝上"（`rotate(-heading)`） |
| 内存 | 100 m 路线 + 32 m 瓦片 → 约 16 张瓦片 ≈ 1 MB（RGB_565），与 Fourier 快照的 1 KB 相比可忽略 |

### 数据结构（Kotlin 草案）

```kotlin
/** 一张世界固定瓦片：覆盖 TILE_METERS² 区域，像素比例固定 */
class MapTile(val tileX: Int, val tileZ: Int) {
    val bitmap = Bitmap.createBitmap(TILE_PX, TILE_PX, Bitmap.Config.RGB_565)
    var dirty = true          // 有新区块/新轨迹 → 需重绘
    var lastUsed = 0L
}

/** 小地图状态：以建图起点为原点 */
class MinimapState {
    var originX = 0.0; var originZ = 0.0     // 世界原点（开始建图处）
    var scale = 4f                            // px per meter
    var northLocked = true
    var followPlayer = false                  // 用户要求默认 false（固定原点）
    val tiles = LinkedHashMap<Long, MapTile>() // LRU，key = (tileX shl 32) or tileZ
    val track = ArrayList<FloatArray>()       // 轨迹点（世界系），>=0.2 m 才追加
}
```

### 绘制顺序（Compose Canvas）

```
1. clipPath(circle)
2. 逐瓦片 drawImage（只画与视口相交的瓦片，源矩形裁剪）
3. 未探索区域以外的底色（可选：整圆铺 #101010）
4. 世界网格（每 10 m 一条淡线，可选）
5. 轨迹折线（青蓝，lineWidth 2dp）
6. 快照点（实验八核心：每 1~2 m 一个圆点；命中过 = 实心）
7. 归巢目标 / 航点图标（色块 + 首字母，越界则贴边画三角）
8. 原点标记（旗/十字，"开始建图处"）
9. 玩家箭头（中心 = playerScreen，随 heading 旋转；北锁时也要转）
10. 外框 + 北向标记 "N"（北锁时固定在上方）
```

### 变换代码（可直接用）

```kotlin
fun worldToScreen(wx: Double, wz: Double, s: MinimapState, cx: Float, cy: Float): Offset {
    val dx = (wx - s.originX).toFloat() * s.scale
    val dz = (wz - s.originZ).toFloat() * s.scale
    return if (s.northLocked) {
        Offset(cx + dx, cy + dz)          // -Z 为北 → 屏幕上方
    } else {
        val a = Math.toRadians(-s.headingDeg.toDouble())
        val c = cos(a).toFloat(); val sn = sin(a).toFloat()
        Offset(cx + dx * c - dz * sn, cy + dx * sn + dz * c)
    }
}
```

### 性能要点（照搬 Xaero 的三条经验）

1. **脏瓦片才重绘**：新轨迹点只标记所在瓦片 `dirty=true`，每帧最多重绘 1~2 张（对应 Xaero 的 `tilesToUpdate` 配额）；
2. **一次离屏、多次复用**：瓦片 Bitmap 常驻，绘制只做 `drawImage` 变换，不做逐像素循环（逐像素是 Xaero 的"安全模式兜底"，手机端禁用）；
3. **亚像素补偿**：平移时用小数偏移，避免瓦片吸附导致的一跳一跳（对应 Xaero 的 `xInsidePixel/zInsidePixel`）。

### 与实验八其他模块的接口

- 里程计（`Fourier 快照归巢` 的"腿"）每帧给出 `(x, z, heading)` → 小地图追加轨迹 + 移动玩家箭头；
- 快照点表 `List<Snapshot(x, z, fftBytes)>` → 小地图 6 号图层；
- 当前归巢矢量 `(dx, dz)` → 从玩家箭头指向前方的黄色箭头；
- 原点 = 第一个快照点（或用户按"开始建图"时的位置）。
